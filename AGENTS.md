# Agent Workflow

## Source of truth for numbers

Tracked result pages live under `result-v2/<suite>/<profile>/<revision>.md`, one page per
measured `(suite, hardware profile, revision)`, and are generated from the raw run under
`data/v2-results/<suite>/<profile>/<timestamp>/`. Do not duplicate result tables into
`README.md` or into docs. Historical reports are not maintained; use git history.

`result-v2/<suite>/INDEX.md` is generated by `scripts/v2/gen_index.py`. Never edit it by
hand.

## Every published number carries its revision

A measurement without the commit it was taken at is not evidence. `run.yaml` records the
measured checkout's path, commit, dirty state and features, the harness commit, the
toolkit commit, the measured binary's path and SHA-256, the host, the thread environment,
the providers, the guard logs and the raw samples. `scripts/v2/validate_run.py` refuses a
manifest whose commit does not resolve in an available checkout; the v2 evidence check
additionally requires clean, committed library, harness and toolkit identities. If you
quote a number anywhere, quote its commit with it.

## The instance corpus is an external input, and that is why there is a launcher

The workload is not compiled into the harness. `cpueinsum-bench` loads the
`tenferro-einsum-benchmark` instance set from a directory given on its command line, and
refuses to run without one (`crates/cpueinsum-bench/src/main.rs:263-266`:
``--instances DIR is required``). The shared recorder drives a harness through one fixed
command line and has no field for a harness input path
(`campaign_toolkit/record_run.py`), so the descriptor supplies the corpus path as
`measured.harness_args`, which the recorder appends to every `verify` and `run` invocation
(never to `info`). That is what binds the pinned harness to the pinned corpus:

* `scripts/setup_extern_deps.sh` materialises `extern/cpueinsum-rs` and
  `extern/tenferro-einsum-benchmark` at the revisions in `pins/`;
* `scripts/build_for_cpueinsum_rev.sh` builds the harness out of the measured checkout and
  installs the artifact as `BIN_DIR/cpueinsum-bench`;
* `measured.binary` names that artifact, so `binary.sha256` is the hash of the binary that
  was measured, and `measured.harness_args` adds `--instances <corpus>` where the harness
  needs it.

Do not vendor the corpus, and do not edit the measured repository to paper over an input
path the descriptor can now declare.

One corpus instance is **not declared**: `str_mps_varying_inner_product_200` is refused by
the harness's own cross-row verification at every thread budget (`MISMATCH(opt_flops)
rel_err=NaN`, exit 1), so a declaration containing it cannot be recorded. The evidence, the
extent probes and the two rejected alternatives are in
`docs/verify-refusal-str_mps-varying-inner-product-200.md`; the exclusion itself lives in
`EXCLUDED` in `scripts/gen_suite_from_census.py` and is printed into the suite's prose and
CI's corpus check. If the harness is fixed, delete that entry and regenerate the suite.

## Timing discipline

One measurement at a time, and **no build while a measurement is running**.
`scripts/v2/record_run.py` holds one campaign-level lock across build, verify and timing for
exactly this reason; a lock inside a per-revision target directory would let a second
recorder build another revision during a measurement. Every timing goes through this
repository's protocol script (`benchmarks/scripts/pinned.sh`, a verbatim copy of the
toolkit's), which pins the cores and checks that those cores **and their SMT siblings** were
idle before and after; a run spoiled by other load is discarded, not published.

The campaign declares `protocol: campaign`, because `cpueinsum-rs` carries no benchmark
protocol of its own; the copy here is the pinned one and is covered by
`default_invalidated_by`-style scrutiny rather than by a measured-repository path. If the
measured checkout ever grows `benchmarks/scripts/`, switch the descriptor to
`protocol: measured` and delete the copy.

Priming is **time-based** (250 ms of wall time per cell) and identical on every row. A fixed
call count is not a substitute: after an idle gate this host reads low for the first second
or two of sustained work, which is large enough to be mistaken for a kernel defect.

A thread budget is declared, not inherited. The harness builds its Rayon pool from the row's
thread count, reads the pool size and the operation budget back, and refuses to report the
request as effective if either was clamped; the recorder removes the ambient thread variables
(`RAYON_NUM_THREADS`, `OMP_NUM_THREADS`) from the measured process's environment first.
`RAYON_NUM_THREADS` matters here: it also lowers `rayon::max_num_threads()`, which the harness
checks a request against, so an inherited value would turn a declared budget into a refusal.

Correctness precedes timing. `cpueinsum-bench verify` must report a clean grid for every
population and thread budget before any timing pass; the recorder enforces this and publishes
nothing otherwise. Verification is a cross-row comparison: the two declared contraction orders
are checked against each other on the same deterministic inputs, plus the harness's refusals of
a single-row selection and of a selection with no second independent result. There is no third
implementation behind it; the page must not imply one.

## Coverage is data, not an apology

The campaign is not run in full on every profile for every commit. A partial run is legitimate:
it is recorded, it is marked `partial` in the index, and it never displaces a full-coverage
report. Do not describe a partial run as if it covered the suite, and do not infer "no
regression" for a population the run did not contain. A cell the harness cannot execute is
recorded as `skipped` with its reason in the run's own CSV and in
`run_spec.populations[].skipped`, not silently dropped; a cell that fails timing is a `failed`
row and the run is not published.

## Checks to run before a push

```sh
python3 -m campaign_toolkit.declarations            # descriptor + suite declarations
python3 scripts/v2/validate_run.py data/v2-results/*/*/*/run.yaml
python3 scripts/v2/gen_index.py --check              # the committed index is regenerated
```

`.github/workflows/ci.yml` runs exactly these, plus a check that the frozen suite still names
exactly the pinned corpus's instances. A rebuilt harness, a regenerated suite or a bumped pin
is a change to what the numbers mean; say so in the commit message.
